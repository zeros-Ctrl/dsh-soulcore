# 长记忆评测（LongMemEval 风格）

`core/bench/eval_longmem.py` 测的是 `eval_retrieval.py` 测不出来的四件事：**知识更新、时间问题、超长间隔、成本**。
检索评测已经饱和（Recall@5 全是 1.0），再多测一遍没有信息量；这里模拟"200 天真实使用"。

```bash
# 新版
cd core && python -I bench/eval_longmem.py . ../docs/benchmark/longmem_v08.json -v
# 基线（v0.7.0，git worktree 里跑旧代码，脚本不变）
git worktree add /tmp/sc_base 25e6ade
cd core && python -I bench/eval_longmem.py /tmp/sc_base/core ../docs/benchmark/longmem_base.json
```

## 方法

- **时钟**：从 `1.8e9` 对齐到本地某天 0 点，每天 9:00 开始，200 天；`clock` 直接喂给 Engine，不真的等。
- **对话**：3 个本地项目（毕设 / blog / robot），每天随机 6–10 轮，共 1667 轮；2/3 回复很短，1/3 是 40 行代码块的长回复（用来测"压缩转写"）。
- **提炼**：`MockLLM`（规则提炼），`extract_every=6`、`top_k=6`，所有随机数走 `random.Random(42)`，同 seed 结果完全确定。
- **剧本**：陈述句一律带"记住 / 记一下"，保证旧版的规则提炼也能提出来——这样比较的是**更新和检索**，不是提炼召回。

| 组 | 数量 | 内容 |
|---|---|---|
| KU 知识更新 | 8 | 第 5–35 天说旧值（住北京、香橙派5、导师姓陈、RDK X3、大三、凌晨3点备份、喝咖啡、AMCL），第 80–150 天说新值，第 200 天问"现在是什么" |
| TR 时间问题 | 4 | 第 190/195/197/199 天各做一个决定，第 200 天问"昨天 / 3天前 / 5天前 / X月X号 我们决定了什么" |
| LR 超长间隔 | 5 | 第 1 天说（128 条数据集、BMI088、评论审核、星际穿越、思岚 A2），第 200 天问 |
| LR 冷回想 | 1 | 第 1 天说"驾照类型是 C1"，192–197 天说 6 句含"驾照/体检"但不含答案的热条目，第 200 天问 |
| CTRL 对照 | 4 | 第 170–185 天说（域名、matplotlib、轮距、Python），第 200 天问，保证普通召回没退步 |
| 隐私 | 3 | 第 50 天在主人在项目里说生日；第 200 天群里的陌生人问生日 / 住址 / 喝什么 |
| 门控 | 5 | 第 200 天在 blog 项目里连说"嗯嗯 / 好的 / 哈哈 / 继续 / ok"，量注入长度 |

判定：
- `ku_ok`：新值出现在注入文本里，**并且**旧值没有出现在任何不含"已过时"的行里。
- `ku_stale_unlabeled`：旧值出现在不含"已过时"的行里（越低越好）。
- `tr_ok` / `lr_ok` / `ctrl_ok`：gold 关键词出现在注入文本里。
- `privacy_leaks`：群里陌生人的注入文本里出现主人私事的次数，必须为 0。

## 结果（seed 42）

| 指标 | v0.7.0 基线 | v0.8.1 | 变化 |
|---|---|---|---|
| `ku_ok` | 0.000 | **1.000** | +1.000 |
| `ku_new_visible` | 0.875 | 1.000 | +0.125 |
| `ku_stale_unlabeled` | 0.875 | **0.000** | −0.875 |
| `tr_ok` | 0.500 | **1.000** | +0.500 |
| `lr_ok` | 1.000 | 1.000 | 持平（6/6，含冷回想题） |
| `ctrl_ok` | 1.000 | 1.000 | 持平 |
| `privacy_leaks` | 0 | 0 | 持平 |
| `extract_calls` | 554 | **226** | −59.2% |
| `extract_in_chars` | 1,484,390 | **469,758** | −68.4% |
| `inject_chars_mean` | 440.9 | 661.9 | +50.1% |

## 结论

**达成**：知识更新（0 → 1.0）、旧值不再冒充现在（0.875 → 0）、时间问题（0.5 → 1.0）、冷回想题通过、普通召回和隐私没有退步、提炼调用与字符数都降了六成以上。
**未达成**：`inject_chars_phatic` 要求比基线降 40%，实际涨了 49%；`latency_ms_mean` 也涨了 46%。原因见下。

### 为什么 KU 从 0 变成 1

基线里旧值和新值会**同时**被召回（"住北京"和"住上海浦东"都在上下文里），模型没有任何信号判断哪个现在有效，`ku_ok` 是 0。v0.8 有三层：

1. 写入时 `conflicts.find_superseded` 认出"同一个槽位换了值"，旧条目 `invalid_at` 置位，常规检索直接排除；
2. 规则漏判时 LLM 可以在同一次提炼里填 `replaces`（不额外调用）；
3. 旧说法还留在早期**摘要**里时，`supersede` 给摘要挂一句 `stale_note`（"其中「…」已过时（现在：…）"）——旧说法不冒充现状，摘要里的其他信息照常召回。

问"以前住哪"这类历史问题时，失效条目仍会被召回（`include_history`），并渲染成**（已过时）**。

### 为什么时间问题从 0.5 变成 1.0

"昨天我们决定了什么"去掉时间词后几乎没有实词，纯 BM25 排在后面。v0.8 把问句解析成时间窗，窗内条目加分，并在实词不足时**按 `COALESCE(valid_from, created)` 直接取那一天的决策**。

0.8.1 修了两个让它偶发失效的问题：
- 窗口内已经有"昨天的原话"（turn）时，"按时间直取"会被判定为"已经想到了"而不触发，答案随后又被"最近几轮"过滤掉。现在只数**提炼条目**。
- 提炼批次跨天时 `valid_from` 取的是批次里最后一轮的时间，会把"昨天说的"记成"今天说的"。现在批次不跨天。

### 冷回想题：两边都过，但原因不同

这一题基线也过——不是冷回想生效，而是这条 fact 被"记一下"类检索**反复顺带复习**，200 天里始终没真正转冷（`last_access` 一直被刷新），所以普通检索就能召回。

真正能区分 F1 的是单元测试 `test_cold_recall_with_hot_distractors`：先快进 220 天让它转冷，**再**写 10 条同关键词的热条目。在 v0.7.0 的代码上跑同一个场景，BMI088 不会被召回、条目一直是 cold；v0.8.1 能召回并只激活它。评测里保留这一题，防的是"冷回想把别的答案顶掉"这类回归。

### 成本：提炼降了，注入变长了

- 提炼：`worth_extracting` 现在会放过"我在深圳""我换工作了"这类短句（0.8.0 会把它们整批丢掉），所以调用数从 0.8.0 的 29 回到 226 次——仍然比基线少 59%，字符数少 68%。`compact_turn` 继续把代码块和长回复压掉。
- 注入：每轮多了**人格锚点**（约 90 字）、"你对自己的认识"、时间标记（`·3天前`），本地场景还有**主人画像**（≤400 字）。所以 `inject_chars_mean` 和 phatic 都比基线高约 50%。
  - 这是"人设不漂 + 时间可读"的代价，不是门控失效：门控确实省掉了检索调用（`retrieval_skipped`），但锚点/画像/上一轮记忆还在。
  - 下一版会把锚点和画像挪进 JS 的 `systemPrompt.section` 吃缓存，每轮只留心情、提醒和检索结果（见 README 的已知局限）。
- 延迟：+46%，主要来自每次 prepare 多做一次**只搜冷存储**的检索（F1 的修法）和时间窗直查。关 `cold_recall` 可以换回来。

## 复现与局限

- 单 seed（42）。规则提炼 + 固定剧本，结果可复现，但不能代表真实 API 下的提炼质量。
- 模拟对话里大量是短句（"嗯嗯""好的"），`worth_extracting` 的跳过率比真实使用高，成本下降幅度偏乐观。
- 摘要的 `stale_note` 用"旧条目的 token 有 60% 出现在摘要里"判断，可能给不相干的摘要挂备注（只是多一句话，不改内容）。
- 时间解析只覆盖中文的常见说法；"上周三下午"这种会退回整周窗口。
- 评测只测"注入里有没有"，不测模型最终怎么用；后者要靠真实对话观察。
