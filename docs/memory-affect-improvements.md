# 可靠记忆、费用统计与情绪行为

本次实现原建议的第 1、2、4、5 项。项目/会话接续卡及 `memory_expand` 暂缓，现有搜索和记住工具继续使用。

## 实际用量账本

`data_dir/usage.sqlite3` 保存模型、用途、输入、缓存命中/未命中、输出、推理、延迟与失败尝试，不保存提示内容或密钥。

插件直接调用的聊天/提炼/画像/摘要，以及 HTTP embedding，使用供应商实际返回的 usage。DSH 钩子透传原始流，同时接收流块实际提供的 usage；累计块只记录最后一份，不逐块累加。没有 usage、模型名或价格时显示未知/未计价，不能当作免费。推理已包含于 output 时不重复收费。

默认启用统计，价格表为空。用当前供应商价格配置 `usage.prices`，键优先采用 `provider:model`，支持这些字段：

- `currency`：币种；不同币种分别合计。
- `input_per_million`、`cached_input_per_million`、`output_per_million`：每百万 token 单价。
- `reasoning_in_output`：默认 true；只在供应商确实独立报告与计价推理时调整。
- `reasoning_per_million`：独立推理单价，按供应商口径配置。

历史请求保存调用当时的价格计算结果，修改价格不追溯重算旧账。总任务比较应包含在线、后台、embedding、失败与返工，而非只比较 prompt 字数。

认证后的 `GET /v1/usage` 可查看汇总，`GET /v1/state` 也返回 `usage`。`POST /v1/usage` 供宿主提交结构化元数据。未接入宿主实际提供的数据时，统计范围会明确显示缺口。

## 原始记录、身份与证据

新增字段包括 `project_id`、`session_id`、`source_event_id`、`source_ids`、`evidence_type`、`evidence`、`epistemic_state`。数据库升级只加表/列，旧记录继续保留。

用户和助手原文保留长度与空白，压缩前先落盘。真实事件 ID 的重复投递幂等；同 ID 内容变更保留独立修订。没有原消息 ID 的压缩材料使用独立抢救编号，重复发言不会只剩一条。

工具结果作为独立 evidence，默认不进入聊天历史或 embedding。DSH 大工具输出保留首尾片段、中段省略数量与原文哈希，避免把大日志全部注入模型。结构化成功退出还必须对应明确的测试运行器，搜索文字“pytest”不算测试通过。`verified` 必须选择有效的工具验证来源，助手自述和普通批次来源不能提供此状态。状态标签会随注入和搜索文本一起输出。

遗忘来源撤下关联的直接及传递派生记忆；修改已验证结论后重新检查状态与证据。删除/恢复沿已有记忆管理接口执行。

### 项目 UUID 的兼容模式

默认 `memory.project_identity = "registry"`：从规范化仓库根目录注册稳定 UUID，同时保留旧 `project/<名称>` 路径。DSH、Claude Code 和 MCP 向同一后端传 cwd，获得同一身份；项目目录内不创建标记文件。

新记录带 UUID，同名项目的检索、提炼水位、摘要和更新按 UUID 隔离。发现同名碰撞后，无明确归属的旧条目暂不作为其中一个项目的事实召回，数据仍保留；状态中显示碰撞与未绑定数量。旧记录不会被自动搬移或认领。

`"strict"` 模式使用 UUID 路径。它会改变旧路径的检索范围，需先处理历史归属后明确启用。项目重命名/移动或跨机器共享时，应显式传原 `project_id`，目录仅是一个别名。

`POST /v1/projects/resolve` 只解析身份与兼容信息，没有生成接续卡。

## 提炼与上下文预算

默认预算：

```json
{
  "memory": {
    "project_identity": "registry",
    "recall_token_budget": 800,
    "context_token_budget": 1000,
    "extract_token_budget": 8000
  }
}
```

这些数字使用本地估算，不能作为账单 token 数。`recall_token_budget=0` 可关闭召回 token 筛选；已有字符设置仍保留。

提炼按说话人、会话、时间间隔、明确话题切换和整轮预算分批。异常 JSON 或不完整结构失败后保留水位；合法空 `memories` 列表才算成功空结果。`coverage` 显示处理到的编号、剩余轮次和最近摘录省略，提炼成功不意味着每个原字符都进入模型。

长文本摘录保留首尾以及中段决定、约束、原因、失败和阻塞，完整原文仍在库中。召回按整条记忆装配；关键决定、待办、置顶和高重要性条目允许超过软预算。画像输入相同则跳过模型调用，稳定规则与画像在提示前部，变化的时间、情绪与检索在后部。

向量查询只使用当前模型空间和正确维度。切换模型期间使用文字检索；改变 embedding 服务/模型版本时可配置独立 `space_id`。默认不会仅因本次升级自动更换旧空间名并触发全库重建。

## 情绪与行为

现有 valence/PID 保留，新增 arousal（唤醒度）。事件先推进旧状态到当前时刻，再注入新驱动，慢心境不瞬间跳变。短驱动衰减、限速和习惯化仍工作；随机状态保存后可重放。

技术方法被批评优先视为任务反馈；人格评价、引用、用户受挫与第三方状态继续区分。关系按人存储，心情与亲近状态保持独立。

`behavior.enabled` 默认 true，任务/直接问题/控制/求助及不确定文本保持完整模型预算。明确闲聊中，开心且兴奋增加相关分享和气泡数，低落减少延展。模型只生成一次，QQ 最多三条自然段；代码、列表和表格保持完整。每条遵守发送检查，后续气泡等待限流最多六秒；打字延迟与发送耗时另计。发送中途失败只写入成功前缀。

概率安静默认关闭，可设置 `behavior.quiet_enabled=true`。仅明确轻闲聊可进入安静，默认最多连续一次，最长十五分钟，之后有冷却；任务与求助可立即唤回，记忆观察和提炼照常。

原有孤独驱动仍保留，它会在长期无人互动时持续影响心情。因此“无持续驱动时回归基线”不等于“长期离线必定回到先天基线”；这个设定可继续用原有 `emotion.w_lonely` 调整。

关闭引擎时会取消独立的看视频任务并唤醒等回复、等发送间隔的线程，总计等待这些线程最多两秒。已经开始的外部请求可能稍后返回；停止后的任务不能再准备上下文或写入已关闭的记忆库。

## 验证边界

本次使用隔离目录、临时数据库、假模型/假 HTTP 与 QQ 回执做回归。验证来源保留、跨项目隔离、异常重试、状态恢复、预算和投递行为；未读取真实记忆库，未进行付费模型实验。

这些测试不能证明真人感或某个节省比例。后续需以真实任务与模型比较最终任务正确率、重要约束遗漏、总费用、延迟，以及情绪适当性与打扰程度。发布后重载插件和 Python 后端才能加载新代码。
