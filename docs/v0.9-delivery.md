## 2. 和任务书 / 官方文档不一致的地方

### 2.1 以官方文档为准的差异

- **Stop 的最终回复**：官方文档（[Hooks 参考](https://code.claude.com/docs/hooks)）现在建议在
  Stop / SubagentStop 上用 `last_assistant_message`，并明确说 `transcript_path` 是异步写入、可能滞后。
  实现改成：**优先用 `last_assistant_message`**，没有才回落到 transcript 解析（解析器按任务书
  2.5 完整实现并有 3 份 fixture 覆盖：普通对话 / 带工具调用 / 带子 agent）。
- **`plugin.json` 的 `author`**：官方 manifest 参考里是对象 `{name, email, url}`，不是字符串。按对象写。
- **SessionStart 的 matcher**：官方支持 `startup|resume|clear|compact|fork`，比任务书多一个 `fork`，
  `hooks.json` 里补上了。
- **`hooks/hooks.json` 需要 `"hooks"` 外壳**：官方文档明确"没有这层包装加载不了"，已按此写。
- **`commands/` 平铺 `.md` 仍然支持**，但官方现在更推荐 `skills/`。任务书指定了 `commands/`，保持不动。

### 2.2 任务书没写、但实现时必须做的决定

- **自启动后端用随机端口**（`serve --port 0`）。任务书只说了怎么启动，没说端口；如果沿用配置里的
  8765，会和用户已有的常驻后端/DSH 抢端口。
- **hook 按 UTF-8 读 stdin、按 UTF-8 写 stdout**。Windows 上 Python 默认按 cp936 解管道，
  Claude Code 传的是 UTF-8，不显式处理会乱码甚至 `UnicodeEncodeError`。
- **`split` 模式下寒暄轮不再重复注入上一轮记忆**。只把稳定块移出去还不够：`inject_chars_phatic_split`
  仍有 558 字（记忆被沿用）。因为 DSH 的历史里还留着上一轮的 snapshot，寒暄轮再注入一遍同样的记忆
  纯属重复，所以 `include_stable=False` 且命中寒暄门控时只注入心情/亲密度。指标降到 **90 字**，
  非 split 模式的 `inject_chars_phatic` 保持 695.4 不变（v0.8 基线完全一致）。
- **`/v1/memory/timeline` 增加 `top` 参数**（按 importance 排序），供 SessionStart 取"最重要的 5 条决策/待办"。
  这是任务书里允许的"或新增一个 top 参数"，属于只增不改。
- **`/v1/memory/search` 增加 `history` 参数和 `created/valid_from/invalid_at` 字段**，
  MCP 的 `memory_search` 工具需要 `include_history` 和"多久以前"，原有字段一个没动。
- **`serve` 的空闲退出只在 HTTP 请求上计时**（不是 tick 线程）：tick 是内部维护，不代表有人在用。

## 4. 已知局限

- **Windows 上靠 POSIX sh 启动器**：插件的 `bin/soulcore-hook` / `bin/soulcore-mcp` 是 `sh` 脚本，
  Claude Code 在 Windows 上通过 Git Bash 执行。没装 Git Bash 时 hooks 可能不生效——
  用 `cc-install`（写 Python 绝对路径）或 `claude mcp add` 这两种方式不受影响。
- **`.mcp.json` 里的 `bin/soulcore-mcp` 在 Windows 上可能无法直接 spawn**（MCP stdio 不走 shell）。
  这是任务书指定的形式；文档里给了 `claude mcp add` 的替代写法。
- **`memory` 风格只影响注入**：情绪、好感、画像照常更新和存储（只是不给你看），
  这是有意的——同一个人格在不同入口共用一份状态。
- **MCP 没做 `roots/list`**（任务书说可选）：项目名取进程启动时的 cwd。
- **K7（真实 LLM 评测）/ K8（OpenAI 兼容代理）没有实现**：任务书标为可选，且 K7 需要用户授权才会花钱调用。
- **`cc-install` 写入的是绝对 Python 路径**：换 Python 环境后要重新 `--apply`。
