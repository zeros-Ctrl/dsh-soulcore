# 开发过程：问题、改进与效果

这轮围绕长期记忆可靠性、成本可观测和人格情绪连续性发展。基线 `d9e5da7`，实现提交 `c40cbd0`；没有实施暂缓的第三项“项目/会话接续卡与按需展开工具”。详细数字见 [实测报告](benchmark/2026-11-memory-affect/README.md)，使用与配置见 [快速上手](quickstart.md)和[配置](config.md)。

## 长期记忆为什么不能只做摘要

上下文压缩和换会话都会丢失当前模型可见的历史。直接将历史裁短后提炼有三个问题：重要条件可能在中段；摘要错误缺少原文可查；助手说“已经完成”可能被写成已验证事实。

改进采用原文、来源、提炼结果分层：先完整保存turn，再生成包含头部与中段约束/理由的有限摘录；提炼条目关联source_ids、session_id、event_id、project_id。结构化工具证据独立保存，提议/接受/实施/验证区分，验证需要相应来源支持。不是所有客户端都一定提供工具证据，因此不能把缺证据的记录自动升级为已验证。

六个压缩抢救样本（962、4636、11060字符的用户/助手材料）新版逐字保存6/6，目标中段摘录1/6→6/6；同消息ID重复投递不会新增重复原始turn。旧版普通聊天本来会保存原文，缺口专指pre_compact抢救路径。

## 同名项目、异常水位与来源污染

### 同名目录不能作为唯一身份

只用basename归档时，两个 `demo` 会碰撞。现在同一home内按规范cwd注册持久UUID，名字保留别名和旧路径，调用和检索携带项目身份。20次合成查询，本项目可见10/20→20/20、其他项目可见10/20→0/20。

迁移选择兼容：不重写所有旧目录；发现名字碰撞时不自动认领不明确的旧条目。搬家、重命名、跨机器仍需显式原project_id或确认迁移，不能只凭同名断定同一个项目。

### 提炼失败不能被当成处理成功

如果模型异常后仍推进指针，重试永远看不到失败批次。现在保存提炼水位和待处理积压，按会话、话题与估算预算分批；异常不推进覆盖，合法空列表才表示成功但无新事实。压缩/会话结束排空积压，维护也处理空闲短聊。

这提升了跟进可靠性，但不能保证任何格式异常都能自动恢复；日志和状态覆盖仍需观察。缩小预算改变本轮材料装配，不删原文，也可能影响可见答案。

### 来源标记引入了新的语义问题

初轮长模拟seed42漏召回Cartographer；seed73关键词检查似乎通过，但当前事实已被误判过时。原因是 `[来源编号#42] 主人: ...` 行首标记被启发式提炼当成说话人和语义的一部分，干扰冲突比较；旧摘要注释里的新关键词又造成假阳性。

修复只剥离行首规范来源标记后再解析说话人与语义，完整原文及结构化source_ids仍保留。新增六项回归，包括Cartographer真实更新链路和X3→X5。评测增加“更新后的有效fact/decision仍在库中”检查，不只看关键词可见。修复后重跑五组，新旧版有效事实检查均100%；初轮不完整诊断不混入最终数据，不自动改写用户历史库。

## 降成本为什么还没达成

原有本地规则、检索门控和短摘录保留；新增不变画像跳过、分批预算、整条召回选择、关键记录保护，以及真实usage账本。20次不变画像反思，调用20→1、输入4300→215字符，此场景减少95%。

但五组200天配对模拟中，平均提炼输入496452→587170字符（+18.3%），每次注入425.9→547.8（+28.6%），调用223.2→224.0，上下文准备97.3→112.0ms（+15.1%）。来源编号、状态、证据和表达提示新增输入。**局部省调用没有抵消可靠性信息的开销。**

预算100时完整答案记录可见43.14%，关键记录100%，平均180.27估算token；相对关闭只省12.4%，却损失56.9个百分点可见率。因此不把默认800降低到100。长期模拟KU40/40、LR30/30、CTRL20/20、隐私15/15两版一致；TR19/20仍共同漏一条，不能宣称长期记忆无缺陷。

后续建议：对来源表示、提炼提示、稳定块缓存做独立消融；用真实usage观察输入、缓存、输出和reasoning，保留项目隔离/有效事实/关键答案/隐私回归门槛。把这轮未实现的方向与现成功能区分，不为了prompt变短牺牲原文或证据。

## 人格为何需要评价、状态和表达分层

“你这个方法错了”应触发任务修正，“你真是个废物”才涉及人格评价；用户失落也不等于角色被辱骂。改进把语言的对象与原因判定放在状态驱动前。四条定向任务批评正确归因2/4→4/4；已有128题均100%、50题留出均96%，没有普遍分类提升证据。

状态层保留原PID和限速，加入独立arousal与随机状态保存。五组重启回放新版mood与连续进程一致，误差0；旧版0.059045是本轮观察，其随机源不持久，不能把该小数当固定效果量。恢复图关闭孤独驱动，产品默认不关闭。

表达层本地计算：高mood高arousal时QQ允许最多3气泡；低mood低arousal的明确轻闲聊可400→260预算，低mood高arousal表达担忧/不满。DSH/local/project及问题、任务、控制、求助保持完整回应。可选安静默认关闭，只针对封闭短私聊寒暄，概率随mood变化，有次数、时间和冷却约束。

目前验证的是状态连续性和策略边界。没有真实模型的生成条数统计、真人感盲评或“更像活人”的结论。情绪状态不是永久人设改写，也不要求角色凭空编造经历。

## 投递、退出与宿主兼容

QQ一次生成后按自然段分条，代码/列表/任务保持完整；只有成功投递的前缀记为助手历史。后续气泡等待有界，中途失败不把未发内容写回。这防止下一轮角色以为自己说过实际没发的话。

独立看视频任务在引擎退出时取消，并在网络调用完成后检查退出状态，避免访问已关闭数据库。集成测试先关闭临时后端再删除目录。设置页usage变量作用域错误移至使用它的组件，新增用量和QQ渲染回归。DSH流式钩子前一版已修复为异步可迭代流，本轮保留兼容。

本机HTTP/1.1连接复用是另一处未提交的本地修改，未纳入上述实现提交和图表效果归因。Windows测试初轮3项WinError10013端口失败，单独6项复跑后，顺序完整381项通过；资源未关闭警告仍存在。39项JavaScript也通过。

## 与其他项目如何公平比较

实测外部对象仅为本机SurfCore实际向量模块：同材料、题目和hash512词法向量，直接调用排序、索引读取和渲染API。SoulCore另有FTS、概念扩展和重排；题库来源于SoulCore，可能偏向其中文概念词表，跨概念小类仅3题。旧版Recall@5已100%，新版也100%，SurfCore78.43%；不能把全部差距归功于本次增强。

SurfCore RAM排序0.20ms、读盘排序2.27ms，SoulCore新SQLite完整检索14.53ms。处理范围不同，不作为整个插件排名。SurfCore项目过滤由外部adapter补充；向量入口素材裁切也不能直接评为完整档案“丢数据”。没有实际跑Mem0/Letta，不借用论文成绩。

## 研究与开源参考如何影响设计

| 参考 | 启发 | 本项目采用/限制 |
|---|---|---|
| [LongMemEval](https://arxiv.org/abs/2410.10813) | 知识更新、时间推理、长距离召回等能力维度 | 用于设计探测类别；本轮合成题不是官方数据集评分 |
| [LightMem](https://arxiv.org/abs/2510.18866) | 分层和延迟处理减少在线负担 | 分批提炼、维护处理和预算；未复现论文架构及成本结论 |
| [MemGPT](https://arxiv.org/abs/2310.08560) / [Letta](https://github.com/letta-ai/letta) | 上下文内外记忆管理、按需访问 | 保留档案、有限注入和工具检索；接续卡/展开工具暂缓 |
| [MemoryBank](https://arxiv.org/abs/2305.10250) | 长期交互的记忆更新与遗忘 | 类型衰减、冷存储、事实更新；关键固定事实单独保护 |
| [Generative Agents](https://arxiv.org/abs/2304.03442) | 观察、反思与行动分开 | 原文、画像/摘要、表达策略分层；画像不变可跳过 |
| [Mem0](https://arxiv.org/abs/2504.19413) / [开源实现](https://github.com/mem0ai/mem0) | 抽取、更新与相关检索 | 参考记忆操作思路，不等于替换为Mem0或取得其成绩 |
| [FAtiMA Toolkit](https://github.com/GAIPS/FAtiMA-Toolkit) / [OCC](https://doi.org/10.1017/CBO9780511571299) | 评价原因、目标和关系，再产生情绪 | 对象/原因归因与事件驱动；没有完整OCC情绪分类 |
| [ALMA](https://doi.org/10.1145/1082473.1082478) / [EMA](https://doi.org/10.1016/j.cogsys.2008.03.005) | 不同时间尺度的情绪/心境、连续评价 | 人设、慢mood、独立arousal、表达分层；不是论文模型复刻 |

这些是设计参考，具体实现、测试与未完成部分以源码和本项目实测为准。使用配置见 [完整参数表](config.md)。
