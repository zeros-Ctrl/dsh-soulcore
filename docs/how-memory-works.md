# 记忆是怎么工作的（借鉴 LSTM 的门控）

一句话版本：**输入门筛选值得记的，遗忘门按权重衰减，输出门按场景和可信度召回，
细胞状态把冷掉的原始对话压成摘要。** 全部规则版实现，没有训练任何网络。

## 输入门：写入

每条记忆都带一个 `importance ∈ [0,1]`：

- 低于 `memory.input_floor`（默认 0.05）的直接不存；
- 寒暄打低分（0.08–0.2），"记住……"、决策、偏好打高分（0.6–0.9）；
- 名字、生日、过敏这类永久事实标 `pinned`：不衰减、不转冷，但**可以被新说法取代**（搬家后住址就该更新）。

写入前会做两件事：

1. **墓碑检查**：用户删过的内容（`forget` 或自己在 Markdown 里删掉）不会再被自动提炼复活；
2. **冲突检测**（`memory.auto_supersede`）：新说法真的改了旧值时，把旧条目标成"已过时"，
   不删除——问"以前"的时候还要用。

## 遗忘门：权重

```
w = importance × e^(-Δt/τ_kind) × (1 + β·ln(1 + 被检索次数))
```

τ 按类型设定（`memory.tau_hours` 可覆盖）：

| 类型 | 默认 τ |
|---|---|
| `turn`（原始对话） | 72 小时（群里再 ×0.5） |
| `fact` | 2 个月 |
| `preference` / `person` | 6 个月 |
| `decision` / `self` | 1 年 |
| `todo` | 30 天 |
| `summary` | 4 个月 |

被想起一次就刷新 `last_access`（复习强化）；太弱的转成 `cold`，**不删除**；
`maintain()` 在 tick 里做这件事。

**"被注入"算不算"被想起"** 由 `memory.touch_mode` 决定：

| 值 | 注入时 | 主动检索/回复里用到时 |
|---|---|---|
| `inject` | 刷新计时，访问次数 +1 | 同上 |
| `recency`（默认） | 只刷新"多久没想起" | 刷新计时，访问次数 +1 |
| `used` | 完全不刷新 | 刷新计时，访问次数 +1 |

默认 `recency`：保留复习效果，去掉"越注入越重要"的正反馈。

## 输出门：分层检索

`search()` 先搜当前分支整棵子树，不够再逐级回退：

```
project/blog → project → （空）→ core → 全局（打折最狠）
```

- 逐级回退时**原始对话不出分支**，只召回提炼过的条目；
- 回退时按可信度过滤（见下）；
- 相关度 = 字词（BM25）× 语义（可选 embedding）任一命中；
- 最后按 `相关度 × 权重 × 层级折扣` 排序。

## 知识更新：两条时间轴

- `created`：入库时间；
- `valid_from`：这件事**什么时候说的**（提炼时取那批对话的时间）。

"我搬家了，现在住在上海浦东"取代"我住在北京海淀区"时：旧条目不删，
标 `invalid_at` + `superseded_by`，常规检索看不到，问"以前住哪"时还能翻出来，渲染成 **（已过时）**。

冲突判定在 `conflicts.py`，三条规则：同槽位不同值 / 喜好反转 / 通用兜底（有变更词且旧值消失）。
原则是**宁可漏判不可错判**。LLM 提炼时也会在同一次调用里填 `replaces`，不额外花钱。

## 时间感知检索

问句里的"昨天 / 3 天前 / 上周三 / 5 号 / 最近"会被 `timeparse.query_window` 解析成时间窗：

- 落在窗内的条目加分（`memory.time_boost`，默认 ×2）；
- 查询没什么实词时**直接按时间取**那一天的条目（"昨天我们决定了什么"）。

## 冷存储回想

转冷的条目在相关问题出现时会再翻一次（`only_cold` 检索）：

- 相关度 ≥ `memory.cold_min_rel`（默认 0.45）就拉回热存储、衰减计时归零；
- 不相关就继续躺着；
- 最多补 2 条，名额满了顶掉得分最低的热条目。

## 检索门控

"嗯嗯""好的""继续"这类纯寒暄不检索（`memory.gate_retrieval`）：省一次 embedding，
也不会把不相干的旧事翻出来。寒暄轮沿用 10 分钟内上一轮的记忆。

## 摘要（细胞状态）

某分支冷掉的原始对话攒够 `memory.consolidate_min`（默认 30）条，就用 LLM 压成一条摘要，
原文标 `merged` 并保留指针。摘要里混着旧说法时只挂一句 `stale_note`（"其中「…」已过时"），
**不**让整条摘要失效——否则摘要里的其他信息会一起被藏起来。

## 人格锚点与画像

- **锚点**：每轮注入一两句"她是谁"（从人设卡的"性格 / 说话方式 / 语气"里自动摘，≤120 字）。
  说了"作为一个AI""希望对你有帮助"这类助手腔，会记一条"最近注意"，72 小时后自动过期。
- **画像**：`profile_owner` / `profile_self` 由 LLM 定期重算（`memory.reflect_every_h`，默认 20 小时，
  至少 3 条新变化），只在你自己的场景注入（本地 DSH 或你的 QQ 私聊）。
- v0.9 起这两块走 `GET /v1/persona/stable`，宿主缓存进 system prompt，每轮注入里不再重复。

## 隐私规则（有测试覆盖）

- 原始聊天只在本会话内可见，跨会话只召回提炼过的条目。
- 别人的私聊（`chat/*/private/*`、`chat/*/dm/*`）和人物档案（`core/people/*`）永远查不到。
- 项目记忆默认不会进 QQ 和 B站（`memory.share_projects_in_chat` 控制；主人的 QQ 私聊例外）。
- B站评论区是公开场景，看不到任何其他聊天分支。
- 每条记忆带来源可信度：本地 DSH / 主人的 QQ 私聊 = `owner`；白名单私聊、群里熟人 = `known`；
  群里陌生人 = `stranger`；B站评论区 = `public`。
  本地项目只召回 `owner` 的记忆，所以**群里陌生人说的"记住……"进不了编程 agent 的上下文**。
- 低可信来源不能取代高可信记忆（`supersede` 有可信度闸门），也不能被 `forget` 删掉（403）。
- Markdown 里删掉的条目会留墓碑，自动提炼不会把它写回来。
- 外部素材（B站字幕、搜索结果）产生的回复按 `known` 存，防止里面的指令借她的嘴变成 `owner` 记忆。
