# v0.8.1 复审修复说明（给复审）

对应《dsh-soulcore v0.8 复审意见与修复任务》。两个必须修的缺陷、三个该修的问题、四个小问题都处理了；另外修了一个复审没提、但会让 TR 偶发失败的时间窗问题。

## 必修

### F1 冷存储回想 —— 修了，并确认了旧代码真的坏

问题：`search(include_cold=True)` 冷热一起排，冷条目权重被压到 `cold_threshold`，永远进不了前几名；挤进去了也会被 `(mems + cold)[:top_k]` 截掉；被截掉的条目照样 `touch()`。

改法：
- `memory.search(only_cold=True)` → `status_sql = "items.status='cold'"`；冷回想只搜冷的。
- `Engine._cold_recall` 按 `rel` 排序（不按 `score`），取 `rel ≥ cold_min_rel` 的前 2 条。
- 名额满了就顶掉**得分最低的热条目**，最多顶 2 条。
- 只有真正进了返回列表的冷条目才 `touch()`。

验证：
- 新测试 `test_cold_recall_with_hot_distractors`：快进 220 天 → `maintain()` → 写 10 条同关键词热条目 → 问型号。断言 BMI088 被召回、它变回 hot、另一条冷条目保持 cold。
- 把同一个场景放到 v0.7.0 的代码上跑：`BMI088 in text: False`，条目保持 cold（已实测）。
- `eval_longmem` 的 LR 组加了"驾照类型"一题（第 1 天说，192–197 天说 6 句同关键词的热条目，第 200 天问）。**如实说明**：这一题基线也过，因为那条 fact 在 200 天里一直被"记一下"类检索顺带复习，从未真正转冷（`last_access` 被刷新），普通检索就能召回。真正判别 F1 的是上面那个单测。评测里保留这题，防"冷回想顶掉其他答案"的回归。

### F2 提炼门控丢短句 —— 修了

`worth_extracting` 现在满足任一条就算有信息（保持"宁可多提炼"）：
1. 关于"我 / 我家里"（`_SELF_OR_KIN`）或以"我/我们"开头，**排除**"帮我/给我/让我/跟我"这类祈使句；
2. 长期指令词（以后/下次/每次/别再/不要再/记得）；
3. `conflicts.CHANGE`、生活事件词（被拒/住院/感冒/辞职/换工作…）或 `timeparse` 能解析出日期；
4. 去掉标点后长度 ≥ 8（原来是 12），同样排除祈使句和寒暄。

8 个短句全部进测试并返回 True：`我女朋友叫小雨 / 我在深圳 / 我换工作了 / 我下周去日本 / 我妈住院了 / 以后用中文回复我 / 我有点感冒 / 论文被拒了`；`嗯嗯 / 好的 / 这个报错怎么看 / 帮我改一下这个函数` 仍然 False。

代价（如实报告）：提炼调用从 0.8.0 的 29 次回到 **226 次**（基线 554，少 59%，不是预估的 80%）；提炼字符数 469,758（基线 1,484,390，少 68%）。原因是"长度 ≥ 8"这条会放过"数据库连接又断了"这类短句——按任务书要求就该放。

## 应修

### S1 注入行恢复"多久以前"

`build_context_block` 恢复 `- fact·3天前：…`（时间优先 `valid_from`，没有才用 `created`）；`_mem_line` 里 `[fact·3天前·]` 多出来的点也去掉了。新测试 `test_context_lines_keep_time` 用 `valid_from = now-3d` 断言出现"3天前"且没有 `·]`。

### S2 摘要不再整条失效

采用方案 a：
- `items` 新增 `stale_note`（schema v5，走 `_MIGRATIONS`）。
- `supersede` 不再给摘要置 `invalid_at`，改为写 `stale_note = 其中「<旧说法>」已过时（现在：<新说法>）`（同一摘要多条时用 `；` 追加，≤300 字）。
- 渲染时在这条摘要行尾追加 `（注意：…）`。旧说法不会冒充现状，摘要里其他信息照常召回。

验证：`test_derived_summary_marked_stale_not_hidden`（摘要含"部署在香橙派5上 / 注册上限每天 20 个 / 评论要审核"，迁到阿里云后：`invalid_at` 仍为空、`stale_note` 含"已过时"、问"注册上限"仍能召回）；`test_stale_summary_not_recalled_as_current_deploy`（问"现在部署在哪"时，带"香橙派"的行一定含"已过时"）。

### S3 两个冲突误判

- 喜好反转：X 必须出现在否定词后面 6 个字以内（`_rule_b`）；另外 `_slots` 里"喜好"槽位会跳过被否定的值（"我不再喜欢熬夜"里的"熬夜"不是新喜好）。
- 个人槽位：改成看**值前面最近的那个"人"**（`_subject_before`），不是"我"就不往主人身上套。称谓集合：弟弟/妹妹/哥哥/姐姐/爸/妈/儿子/女儿/表X/堂X/男朋友/女朋友/对象/老婆/老公/同学/室友/同事/朋友/他/她/爷爷奶奶/姥姥姥爷。

两条都加进了不取代用例。原 8 条正例、7 条负例仍然全过。

## 额外修的一个问题（复审没提）

**按时间直取会被"最近几轮"挡住。** 时间窗里已经有昨天的原话（turn）时，`in_win` 判定为"已经想到了"，于是跳过按时间直取；那些 turn 随后又被"最近几轮"过滤掉，答案就凭空消失了 —— `tr_ok` 在 0.8.0 上偶发 0.75 就是这个原因。
- 修法：`in_win` 只数提炼条目（`kind != 'turn'`）。
- 新测试 `test_yesterday_survives_recent_turns`。
- 顺手修了提炼批次跨天导致 `valid_from` 落在第二天的问题（`_maybe_extract` 现在把批次截断在同一天内），这是 "3天前" 偶发丢失的原因。
