## 和任务书不一致 / 任务书没写但做了的地方

1. **`is_phatic` 的判定顺序反了。** 任务书先查提示词再匹配整句，但"在吗"既在整句名单里、又含"吗"，按原顺序永远判不成寒暄。现在先匹配整句，再看提示词。其余规则不变。
2. **摘要也会被标失效。** `supersede()` 会顺手把"60% 以上的 token 都出现在旧条目里"的同路径摘要一起置 `invalid_at`。不加这一条，`ku_stale_unlabeled` 下不去：旧说法留在三个月前的摘要里，她照样会复述。摘要失效不删除，问"以前"时仍可召回。
3. **`profile_dirty`。** 主人的条目被取代后，旧画像里还抄着旧值。现在 `supersede()` 给 `core/people/*`、`core/self/*` 打脏标记，下一次 `tick()` 无条件重算画像（不受 20h / 3 条新变化的限制）。
4. **提炼门控的开关叫 `memory.extract_gate`**（默认 true）。任务书只说"接入"，没给名字；约束 6 要求所有新逻辑有开关。`segment_gap_min` 用的是任务书给的名字。
5. **`_extract_job(..., force=False)`。** `pre_compact` 的抢救路径要跳过门控，所以加了参数；`_maybe_extract` 里 `force=True` 也会透传。
6. **`extract_full()` 多一个 `limits` 参数**（把 `memory.extract_assistant_chars/user_chars` 传进去），默认值仍是 300 / 800。
7. **寒暄轮不注入画像。** 门控命中时 `profile_owner/self` 传空——"嗯嗯"不需要把"关于你的一切"再背一遍。锚点仍然注入（任务书要求优先级最高）。
8. **`_save_emotion` 加了重试。** 本机跑 200 天模拟时，Windows 上 `os.replace` 偶发被占用（杀毒/索引），一次就让常驻进程崩掉。现在重试 3 次、失败只记警告。
9. **后台提炼任务加了 `add_done_callback` 日志。** 之前任务里的异常会静默消失（调试时踩到：`supersede` 里一个变量顺序写错，导致提炼悄悄停了 100 天没人发现）。
10. **`persona` 新增 `anchor / anchor_enabled / slip_ttl_h`，`memory` 新增 9 个键**，都写进了 `config.example.json`。

## 已知局限

- **`inject_chars_phatic` 未达标**：要求比基线 −40%，实际 +27%。原因是锚点（~90 字）常驻、且门控按任务书仍沿用上一轮记忆；200 天后基线本身的注入就很短（489 字）。详见 `docs/benchmark/LONGMEM.md`。
- **`latency_ms_mean` +70%**（46 → 79 ms）：每次 prepare 多一次冷存储检索和时间窗直查。关 `cold_recall` 可以换回来。
- **`lr_ok` 没有"高于基线"**：基线已经 1.0，只能持平。
- **摘要失效是启发式**（token 覆盖率 ≥0.6），可能误伤包含同类词的其他摘要；失效可恢复，但会少一段上下文。
- **时间解析**只覆盖任务书表里的说法；"上周三下午"会退化成整周窗口，"两三天前"不认。
- **LLM 的 `replaces` 只取 3 个**，冲突检测也最多取代 2 条（任务书要求），一次改多个槽位时可能漏。
- **画像质量取决于 LLM**；规则版（Mock/无 key）就是把条目拼起来，可能又长又碎。
- **单 seed**：长记忆评测只跑了 seed 42，规则提炼 + 固定剧本可复现，但不代表真实 API 下的提炼质量。

## 验证情况

- `cd core && python -m unittest discover -s tests`：**169 个全过**（原 114 + 新增 55，原有断言一个没改）。
- `python -I bench/eval_retrieval.py`：各组 Recall@5 = 1.0、`privacy_leaks = 0`（基线同样 1.0）。
- `python -I bench/eval_longmem.py`：见 `docs/benchmark/LONGMEM.md`。
- **JS 测试没能在本机执行**：`node --test tests/plugin.test.mjs` 在受限 shell 里 `spawn EPERM`（子进程管道被沙箱拦，属于环境限制）。JS 侧一行没改，`npm test` 现在多跑 55 个 Python 测试。
- 本机沙箱不允许 `tempfile.mkdtemp()` 写 0700 目录，跑测试时用了一个 `sitecustomize` 垫片（只在本机命令里通过 `PYTHONPATH` 注入，**不在仓库里**）。`python -I` 会忽略它，所以本机的评测命令实际是 `python -B`；在正常环境里 `-I` 可直接用。
